# 교수자용 정답/해설 및 운영 가이드

## 채점 공통 기준
A: 실습 재현 가능, 정량 성능 측정, 오류 원인 분석, 안전수칙 준수, 개선안 제시가 모두 충족된다.
B: 기능 구현과 기본 측정은 충족하나 분석 깊이나 개선안이 부족하다.
C: 실행은 되었으나 버전/로그/정량값 기록이 불완전하다.
D: 결과 재현이 어렵고 안전 또는 절차 누락이 있다.
F: 미제출 또는 실습 수행 증거가 부족하다.

## 주차별 해설 포인트
1주: Jetson 실습의 핵심은 버전 재현성이다. 학생이 모델명, JetPack, L4T, CUDA, Python, OpenCV를 모두 기록했는지 확인한다.
2주: GPIO 안전을 가장 엄격히 본다. 3.3V 로직, 저항 사용, GND 공통 여부를 확인한다.
3주: FPS 저하는 픽셀 수 증가, USB 대역폭, CPU 전처리, 디스플레이 비용으로 설명할 수 있어야 한다.
4주: GPU 성능 측정은 warm-up과 synchronize가 핵심이다. 단일 측정값보다 반복 평균이 바람직하다.
5주: PyTorch에서 model과 tensor가 같은 device에 있어야 한다. latency 측정에는 첫 실행 제외가 필요하다.
6주: TensorRT는 추론 최적화 도구이며 학습 도구가 아니다. FP16 결과 검증을 요구한다.
7주: 오검출/미검출 사례 분석이 중요하다. 학생이 threshold와 입력 해상도를 조정했는지 확인한다.
8주: 중간 프로젝트는 통합 안정성과 병목 분석에 가점을 둔다.
9주: ROS 2는 모듈화와 확장성의 관점에서 설명되어야 한다.
10주: frame_id와 timestamp 누락은 실습 감점 요소로 둔다.
11주: 센서 데이터는 예쁘게 보이는 것보다 노이즈와 결측 분석이 중요하다.
12주: SLAM은 환경 조건과 주행 방법이 결과에 큰 영향을 준다.
13주: AI 결과를 바로 제어에 연결하지 않고 상태기반 안전 로직을 넣었는지 확인한다.
14주: 최종 평가는 시연 성공만이 아니라 요구사항 추적성, 시험표, 실패분석, 안전계획을 함께 본다.
